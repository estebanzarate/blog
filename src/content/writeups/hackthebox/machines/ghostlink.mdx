description: "Cuenta con un controlador de dominio de Active Directory y un servidor web. La enumeración revela un servicio MQTT crítico utilizado para el seguimiento de nodos, que expone dos hosts internos: una aplicación segura para compartir archivos y un host de código de Gogs. El atacante modifica la comprobación de estado de MQTT para activar la autenticación NTLM, retransmitiendo credenciales para autenticarse como la cuenta de servicio svc_canary. Utilizando esta autenticación, el atacante explota una vulnerabilidad de recorrido de ruta con doble codificación URL para extraer el archivo ntuser.dat de la cuenta de servicio. El análisis del registro revela un documento reciente para db.zip, que contiene credenciales de KeePass para la aplicación Gogs. Estas credenciales se utilizan para explotar una vulnerabilidad RCE CVE-2025-8110 en Gogs y obtener acceso. Una vez en el sistema, el atacante descifra un hash de Gogs para iniciar sesión como el usuario local nvirelli. Por último, la vulnerabilidad ESC11 en ADCS permite al atacante solicitar un certificado de controlador de dominio y comprometer el dominio."

El servicio que llama la atención es el servicio o protocolo MQTT (Message Queuing Telemetry Transport) que transporta datos de manera ligera entre dispositivos con recursos limitados, siendo el estándar principal para el Internet de las Cosas (IoT) y la domótica.

- **Modelo de publicación/suscripción**: Los dispositivos no se comunican directamente entre sí. Usan un servidor central llamado bróker o agente.
- **Publicación**: Un dispositivo (cliente editor) envía información (como la lectura de un sensor de temperatura) etiquetada bajo un tema o topic específico hacia el bróker.
- **Suscripción**: Otros dispositivos (clientes suscriptores) le piden al bróker recibir los mensajes de esos topics particulares para reaccionar ante ellos.
- **Optimización de recursos**: Consume muy poco ancho de banda y energía, lo que permite su uso en microcontroladores, sensores pequeños o redes lentas.
